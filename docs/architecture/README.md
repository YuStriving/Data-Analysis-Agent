# 系统架构：模块怎样配合

本目录帮助你了解系统由哪些部分组成、它们怎样连接，以及目前有哪些实现缺口。第一次阅读系统结构时，从这里开始。

## 本目录里的文件

| 文件 | 用途 |
| --- | --- |
| `README.md` | 本页：介绍当前架构和未来架构的区别 |
| `current.md` | 当前系统地图：根据现有源码整理模块职责、主要入口和已知缺口 |

目前没有已确认的全局未来蓝图，因此这里不会把建议或设想写成已决定的目标。等相关设计确认后，再新增目标架构文档并从本页链接。

## 当前图和未来蓝图有什么区别

- **当前架构**描述代码现在是什么样。地图中出现一条连接，只说明代码入口或职责之间有关联，不代表整条功能已经端到端验证。
- **目标架构**描述确认后希望系统变成什么样。它必须有已确认的设计或需求作为依据；没有依据时不创建空文档。

要了解某个技术方案为什么这样设计，请看[详细设计说明](../design-docs/README.md)。需要了解项目必须遵守的共同规则，请看[总体设计约束](../DESIGN.md)。

## 维护时怎么做

- 修改 `current.md` 前，对照源码确认实际职责和入口；不能根据计划推断功能已经实现。
- 将来添加目标架构时，链接到已确认的设计和需求，并明确标出尚未实现的部分。
- 如果内容只是某个模块内部的方案，放到对应模块文档或[详细设计目录](../design-docs/README.md)，不要重复写进全局地图。
