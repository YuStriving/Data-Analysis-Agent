# 待办开发协作约定

本目录是待办开发行为规范和 spec 文档的统一存放位置，路径为项目根目录
`spec/`（`C:\Users\17924\Desktop\agent项目\spec`）。当前用于
`backend-agent` 待办事项的 spec 讨论、确认和验收记录。
遵循根目录 [agent.md](../agent.md) 和模块 [agent.md](../backend-agent/agent.md)。
本约定依据用户明确提出的两条规则：先讨论 spec，再开展具体工作；
所有工作产出都需要积累测试用例。

## 先讨论 spec，再实施

- 每项待办先阅读相关代码和规范，说明当前行为、问题及依据。
- 在本目录记录 spec，明确目标、MVP、非目标、输入输出、职责归属、
  影响范围、异常与边界行为，以及验收和测试场景。
- 行为规范统一维护在本文件，每项待办 spec 在本目录按事项单独建文档；
  模块规范只保留入口链接。
- 先与用户讨论关键问题、推荐方案及取舍；未确认的内容标记为待确认，
  不把假设直接作为实现要求。
- 用户确认 spec 且关键信息充分后，给出
  【当前信息足够，可以开始进行编码】提示，再按确认的内容实施。
- 实施中发现范围扩大、契约变化或关键假设不成立时，先更新 spec 并讨论
  确认，再继续受影响的实现。

## 所有产出积累测试用例

- spec 讨论阶段就记录验收行为，并在根目录 `tests/` 记录详细测试用例。
- 每个用例至少包含标识、关联需求、前置条件、输入或操作、预期结果。
- 用例按实际行为覆盖正常路径、异常路径和边界；涉及权限、数据隔离或
  安全策略时，必须包含拒绝和越权场景。
- 功能、缺陷修复、重构、提示词和配置变化，应新增或更新对应的可执行
  测试或评测；缺陷修复保留复现用例，重构验证既有行为和契约。
- 测试方案、用例说明和验证记录统一放在根目录 `tests/`；可执行测试保留
  各模块现有目录，spec 引用测试方案与用例编号，不重复维护详细用例表。
- 纯文档或方案产出也要保留可复核的验收案例、检查步骤和预期结果；
  尚不能自动化的用例注明原因及验证方式，不能只写“已检查”。
- 交付时记录执行命令或检查步骤、实际结果、未执行项及原因。
  测试未通过或关键场景未验证时，不将待办标记为完成。
- 验证以本次影响范围和关键路径为主，避免无依据地扩大为全量测试。

## 每项 spec 的最小记录

1. 背景与现状依据。
2. 目标、MVP 和非目标。
3. 行为与契约、职责及影响范围。
4. 推荐方案、取舍、风险与待确认问题。
5. 验收标准及集中测试方案的引用。
6. 讨论结论和用户确认记录。
7. 实施任务与集中测试验证记录的引用。

讨论中的验收用例和实施后的测试结果分别记录，不能将预期结果当作已通过。
