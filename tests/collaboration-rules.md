# 协作规范验收方案

关联规范：[spec/README.md](../spec/README.md)。

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| RULE-01 | 新待办尚未确认 spec，准备修改代码 | 先讨论并确认范围、行为和验收场景 |
| RULE-02 | spec 已确认且信息充分 | 给出编码提示，按确认内容实施并关联用例 |
| RULE-03 | 实施中出现影响契约或范围的新要求 | 更新 spec，确认后继续受影响的实现 |
| RULE-04 | 交付功能、修复、重构、提示词或配置 | 有可执行测试或评测及实际结果 |
| RULE-05 | 交付纯文档或方案 | 有可复核验收案例、检查步骤和结果 |
| RULE-06 | 测试失败或关键用例未执行 | 明确缺口，待办保持未完成 |
| RULE-07 | 规范统一迁移到根目录 spec | 新位置与入口有效，旧文件移除，原规则编号保留 |
| RULE-08 | 测试方案集中到根目录 tests | spec 只引用方案，完整用例与记录不重复维护，可执行测试保留模块位置 |

验证：检查所有本地 Markdown 链接；逐一核对规则；确认 RULE 编号唯一完整、
spec 不含详细案例表，backend-agent/pyproject.toml 测试发现目录未迁移。
2026-10-03 实际结果：RULE-01/02 按用户确认计划实施；RULE-03 的授权 None 契约在
design 中明确并经过独立复核；RULE-04/06 的关键测试 127 passed，无跳过；RULE-05/07/08
核验 11 份文档、38 个本地链接、8 个规则编号、10 个用例组和 48 个测试函数引用。
根目录 spec/README.md 仅引用详细方案；测试代码及 pytest 发现目录未迁移。
具体命令、结果与验证边界见 [tool-calling.md](tool-calling.md) 的 V1～V4 记录。
